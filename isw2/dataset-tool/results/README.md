# Milestone 2 results

Generated by `isw2.openjpa.m2`, from the Milestone 1 dataset (`../data/dataset.arff`,
14,769 rows, 17 features, 20.3% buggy). Methodology, decisions and threats to validity are
in `../../docs/PROVIDED_CODE_CHANGES.md`, section "Milestone 2".

The intermediate files under `../data/` are gitignored because they are regenerable. These
six are versioned because they take roughly three hours of compute to reproduce and they
are the answer to the milestone.

## The deliverable

### `m2_results.csv`
The table Milestone 2 asks for. Columns and row order exactly as in the provided
`15_2_ExampleOfOutputD2M2.csv`:

```
Dataset,Classifier,FS,Balancing,Precision,Recall,AUC,Kappa,NPofB20
```

12 rows: 3 classifiers (RandomForest / NaiveBayes / Ibk) x FS {No,Yes} x Balancing
{No,Yes}. Validation is 10 times 10-fold, seeds 1..10. `Balancing = Yes` means
`Resample -B 1.0 -Z 159.46` (oversampling); see M2-C1 in the methodology document for how
that constant is derived.

Feature selection and balancing are both fitted inside a `FilteredClassifier`, so neither
is ever fitted on data that includes the fold being predicted.

## Supporting evidence

### `m2_detailed.csv`
Every cell of the matrix, every metric, with the mean, the sample standard deviation and
all ten per-repetition values. 18 cells x 6 metrics = 108 rows. Use this to judge whether a
gap between two classifiers is larger than the run-to-run noise; the deltas discussed in
the report are one to two orders of magnitude above it.

### `m2_balancing.csv`
The three techniques from `13_1_Balancing.pdf` compared side by side - none,
`SpreadSubsample -M 1.0`, `Resample -B 1.0 -Z 159.46`, `SMOTE -P 293.29` - with feature
selection held off. The milestone collapses this into one Yes/No column; this is the table
behind the choice. Includes PofB20 next to NPofB20.

### `m2_features.csv`
How often `CfsSubsetEval` + `GreedyStepwise(backwards)` kept each of the 17 metrics, over
all 100 training folds. CFS is a filter method, so the subset for a given fold does not
depend on the classifier - the same table results from any run.

### `m2_walkforward.csv`, `m2_walkforward_steps.csv`
Not required by Milestone 2. Walk-forward validation - train on releases 1..k, test on
release k+1 - which is the technique used in the RQ2 methodology of `12_Npofb20.pdf`. The
summary file averages the 13 steps; the steps file gives each one with its training size,
so the learning curve is visible.

Added because random folds let a model recognise the file rather than predict the defect: a
predictor given only a file's identity scores AUC 0.913 on this dataset. See M2-T1.

## Reproducing

From `isw2/dataset-tool/`, with `data/dataset.arff` present:

```
mvn -B compile

# the 12-row table, the balancing comparison and the CFS frequencies
mvn -q exec:java -Dexec.mainClass=isw2.openjpa.m2.ClassifierEvaluator

# the walk-forward tables
mvn -q exec:java -Dexec.mainClass=isw2.openjpa.m2.WalkForwardEvaluator
```

Output lands in `../data/`; these copies were taken from there.

`ClassifierEvaluator` accepts classifier names as arguments (`RandomForest`, `NaiveBayes`,
`Ibk`) to run a subset, and `--required-only` to skip the balancing comparison. Note that
each run rewrites the CSVs from that run's results alone, so a partial run produces a
partial table - the files here were assembled from two runs.

Everything is seeded (folds 1..10, filters `-S 1`), so the numbers reproduce exactly.
Roughly three hours on a laptop; IBk and SMOTE dominate.
